## 2. Enforcement of `config/dataset_gates.yaml` & Source-Label Confounding Math

Inspection of [`config/dataset_gates.yaml`](file:///d:/Project/IFSI-for-phishing-email-detection/config/dataset_gates.yaml) and [`src/tools/diagnostics/confounding_audit.py`](file:///d:/Project/IFSI-for-phishing-email-detection/src/tools/diagnostics/confounding_audit.py) confirms the following binding primary-corpus gates:
- **`maximum_source_fraction: 0.40`** — **Preserved strictly without relaxation.** No single upstream corpus may contribute $> 40\%$ of Track A.
- **`minimum_minority_fraction: 0.20`** — Preserved (`50% / 50%` target balance).
- **`minimum_test_records_per_class: 300`** — Preserved (`>= 300` Legitimate and `>= 300` Phishing test records; `>= 600` minimum total).
- **`confounding.source_only_balanced_accuracy_max: 0.65`**, **`format_only_balanced_accuracy_max: 0.85`**, **`full_minus_format_balanced_accuracy_min: 0.05`**.

### Mathematical Proof of the Single-Class Confounding Trap
In [`confounding_audit.py`](file:///d:/Project/IFSI-for-phishing-email-detection/src/tools/diagnostics/confounding_audit.py) (lines 112–128), `source_only` balanced accuracy fits a `OneHotEncoder(handle_unknown="ignore")` classifier over the `source` tag. For a class-balanced dataset ($N_0 = N_1 = N/2$) partitioned across sources $s \in S$ with class counts $(n_{s,0}, n_{s,1})$, the Bayes-optimal in-corpus `source_only` balanced accuracy on a random split is:

$$\text{BA}^*_{\text{source-only}} = \frac{1}{N} \sum_{s \in S} \max(n_{s,0}, n_{s,1}) = \frac{1}{2} + \frac{1}{2N} \sum_{s \in S} |n_{s,0} - n_{s,1}|$$

- **Critical Implication 1**: Even if Track A uses 10 completely independent sources (each $10\% \le 40\%$), if every source is **single-class** ($n_{s,0} = 0$ or $n_{s,1} = 0$), then $\sum_s |n_{s,0} - n_{s,1}| = N$ and **in-corpus $\text{BA}^*_{\text{source-only}} = 1.0000 > 0.65$**! Satisfying in-corpus $\text{BA}^*_{\text{source-only}} \le 0.65$ requires at least **$70\%$** of records to originate from balanced **dual-class** sources ($\sum_s |n_{s,0} - n_{s,1}| \le 0.30N$).
- **Critical Implication 2 (`held_out_source` vs. Within-Track-A Reporting)**:
  1. Against IFSI's frozen training/RAG split (`train = clean_split_v1/train.jsonl`, `test = Track A`), **zero** shortlisted Phase 8.1B sources (`trecc07p`, `ietf_mailarchive`, `asf_lists_mbox`, `phishing_pot`, `untroubled_phish`) appear in `train`, so `OneHotEncoder(handle_unknown="ignore")` yields **`source_only_balanced_accuracy = 0.5000 <= 0.65`**.
  2. Within Track A itself, pairing `trecc07p` (`30%` dual-class: `120` legit + `120` phish on the **identical live receiving MTA**, internal $\text{BA}_{\text{source-only}} = 0.50$) with `4` contemporary single-class sources (`70%` total) yields an in-Track-A random-split $\text{BA}^*_{\text{source-only}} = 0.85$. Therefore, **headline binary accuracy/MCC/F1 must NEVER be claimed only on the pooled 5-source union without**:
     - Reporting the **internally unconfounded `trecc07p_dual` slice (`N = 240`, `BA_source = 0.50`)** separately using full binary metrics (`Precision`, `Recall`, `FPR`, `MCC`), **and**
     - Reporting **per-source `Recall`** on each phishing source (`phishing_pot`, `untroubled_phish`) and **per-source `FPR`** on each legitimate source (`ietf_mailarchive`, `asf_lists_mbox`) per [`config/corpora.yaml`](file:///d:/Project/IFSI-for-phishing-email-detection/config/corpora.yaml) (`metrics_policy: "recall_only"` / `"fpr_only"`), **and**
     - Enforcing symmetric header canonicalization so `format_only_balanced_accuracy <= 0.85`.
